### Докачка `clubs.json` (`topup.py`)

`data/full/clubs.json` расширяется скриптом `topup.py` (докачка недостающих клубов
до скачиваемых лиг). Алгоритм:

- **Источник**: все клубы из `data/clubs.json` (4574), фильтр — клуб входит хотя бы в одну
  из **266 скачиваемых лиг** `tournament_structure.json` (tiers + youth; 238 базовых +
  топ-лиги 24 стран без структуры + PLI3 + UA2P) и отсутствует в `data/full/clubs.json`.
- **2 запроса на клуб**: `clubs/{id}/profile` + `clubs/{id}/players`, HTML-бакет
  (адаптивная скорость, circuit breaker). Профиль даёт авторитетные страну и лигу —
  клуб вмердживается без эвристик по `leagues[]`.
- **Формат**: новые страны/лиги/клубы добавляются в существующую вложенную структуру
  (порядок старых записей сохраняется), файл сбрасывается атомарно (`.tmp` → `os.replace`)
  каждые `--flush` (50) клубов — прерывание безопасно.
- **Картинки** (после профилей): единая фаза сканирует **весь файл** (логотипы клубов/лиг,
  флаги, лица) — CDN-бакет, one-shot (`max_retries=1`, не открывает circuit),
  mirror-fallback на `tmssl.akamaized.net` (img.a флапает 502/504), существующие файлы
  и плейсхолдеры `default` пропускаются, прогресс-лог каждые 2000 лиц.
- **Resume**: SQLite-кэш — успехи кэшируются, провалы нет; повторный запуск продолжает.
  Провалы с пустым `league` в профиле (нет места в структуре) попадают в failed-список.

Запуск: `.venv\Scripts\python topup.py` (все) / `--limit N` (частично) / `--no-images` /
`--images-only` (только догон картинок).

Примечание: структура использует «игровые» id лиг (ARG1, MEX1, TDeA…), а клубы в файле лежат
под реальными TM-id (ARGC, MEXA, TDeC…) — конвертер должен маппить id структуры → TM-id.
Готовая карта — `data/league_id_map.json` (`structure_to_tm` / `tm_to_structure`): 13
рассинхронизированных лиг из 266, остальные 252 — identity, 1 без данных (SFAL — кубок MTN8).

### Источники полей

| Поле | Источник |
|---|---|
| позиция, рост, фут, дата рождения, гражданство, стоимость | `clubs/{id}/players` (состав клуба) |
| `national_team_id`, `shirt_number` | `national-teams/{id}/players` (только здесь) |
| `coach_id` | прямой парсинг `/mitarbeiter/verein/{id}` (API не отдаёт) |
| colors, стадион, лига, основан | `clubs/{id}/profile` |
| `outfitter`, мульти-позиции | `players/{id}/profile` (точечно) |
| `max_market_value` | `players/{id}/market_value` (история); fallback — ceapi TM |

Поля `weight` и `flag` канон не несёт: в TM их нет (эвристика конвертера) / API не отдаёт.

## Промежуточные/исторические форматы (main, не используются новым конвейером)

`tm_players_urls.json`, `tm_players_profiles.json`, `tm_players_market_values.json` и
`prepared_tm_*.json` — выход старого конвейера `tm_1…tm_999` для football_collection; новый
конвейер пишет только канон, `prepared_*` собирает конвертер.

## Ловушки

- `market_value` из API — уже число (валидаторы `parse_str_to_int`); строка «€30.00m» бывает только
  в сырых HTML.
- `max_market_value` — максимум по истории; при `null` в истории игнорируется (без TypeError).
- Роль/позиция — TM-перечисление (13 значений), не GF-роли; маппинг делает конвертер.
- `shirt_number` в каноне — строка (приводится в build_canon).
