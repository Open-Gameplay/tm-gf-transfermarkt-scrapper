## Не подтверждено

- **tmapi稳定性**: `tmapi.transfermarkt.technology` — внутренний JSON API TM, reverse-engineered
  из JS-бандлов. Не публичный, может измениться без предупреждения. Пока работает стабильно.
- **Лимит HTML 8 rps — история эксперимента, не рабочий режим.** Прямой probe показал: короткие
  серии чисто даже на 75 rps burst, но чувствительные страницы (`/profil/spieler/`,
  `/marktwertverlauf/`) блокируются по объёму уже после ~15-24 подряд запросов. Поэтому устойчивый
  безопасный лимит — **2.0 rps** (`TM_HTML_RPS`, см. `config.py`); 8 rps годятся только для коротких
  фаз (составы) и для CDN.
- **429/Retry-After не наблюдались** — логика ретраев их уважает, но эмпирически не проверена.

## Известные болячки (задокументированы, не блокеры)

- tmapi не отдаёт socialMedia, relatives, trainerProfile, club details — бесполезно для GF.
- `national_teams.flag` — источника флага в API нет (только эмблема).
- `players.weight` — в TM нет, эвристика в конвертере (не поле канона).
- `competitions.logo` — из лиг Tier-1 не достаётся, null.

## Отложено (вне этой сессии)

- **Player extras для всех 107k** (stats/inj/ach/trans) — ~535k запросов, weight=2, ~6 дней на 2 rps.
- **Конвертер канона → GF SQLite** — роль исполняет **`tm-gf-import`** (соседний репо); в data v2
  переводится на плоский `data/canon/`.
- **Конвертер канона → Flutter `prepared_*.json`** для football_collection.
- `national_teams.flag` — источника флага в API нет (только эмблема).

## Отвергнуто

- open-football-database как основной источник атрибутов — TM напрямую доступен через tmapi.
  Ofdb отложена в долгий ящик: может перестать поддерживаться, не является зависимостью.
- HTML-скрейпинг профилей игроков — заменён на tmapi JSON.
