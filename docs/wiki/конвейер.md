# Конвейер

## Что это

Клиент-скрейпер: дёргает локальный transfermarkt-api (:8000), скачивает фото, чистит данные и
собирает `prepared_*.json` для football_collection. Путь: API → `tm_1…tm_999` → финальные файлы.

## Порядок скриптов

```
tm_1_teams_2        сборные (48) + игроки (tm_players_urls.json) + тренеры (tm_coach_profiles.json)
tm_1_2_filter_coaches_by_teams   тренеры только тех, кто в командах
tm_2_players_profiles_2          профили игроков (tm_players_profiles.json) + tm_clubs_urls.json
tm_3_legends_profiles            легенды (legends_ids.json → tm_legends_profiles.json)
tm_4_market_values_2             стоимости (tm_players_market_values.json)
tm_4_2_filter_market_values_by_players_profiles
tm_5_clubs_2                     профили клубов (tm_clubs.json)
tm_5_2_filter_clubs_by_players_profiles
tm_6_load_images_2               фото: flags/, players_faces/, legends_faces/, coach_faces/, logos/
tm_7_compress_images_2           PNG → JPG (папки *_compressed/)
tm_999_prepare_data              чистка → prepared_*.json
```

Пары «скрипт → эндпоинт API»: `tm_2`/`tm_3` → `/players/{id}/profile`; `tm_4` →
`/players/{id}/market_value`; `tm_5` → `/clubs/{id}/profile`; `tm_1` → `/coaches/{id}/profile` +
прямой скрейпинг страниц сборных и `/mitarbeiter/`.

## Промежуточные файлы

| Файл | Что |
|---|---|
| `tm_teams.json` | сборные + player_id списки + coach_id |
| `tm_players_urls.json` | игроки: id, name, url, photo_url, number, team_id/name |
| `tm_players_profiles.json` | сырые профили от API (до tm_999 — вложенный `profile`) |
| `tm_players_market_values.json` | стоимость + история + ranking |
| `tm_clubs.json` | профили клубов от API |
| `tm_coach_profiles*.json` | тренеры |
| `legends_ids.json` | ручной список легенд `{name, id}` |
| `prepared_tm_teams_emblems.json` | id сборных с эмблемой |

## Известные баги (см. AGENTS.md)

- 0 задержек, 8–20 воркеров, статичный UA — баны TM; ретраи только 503.
- `tm_999` неидемпотентен — перезаписывает вход, второй прогон разрушает данные.
- `tm_998` избыточен при верном порядке; фильтры `tm_4_2`/`tm_5_2` хрупки к формату после `tm_999`.
- Потенциальный `TypeError` при `null` в истории стоимости.
- `tm_7`: фон белый, хотя комментарий обещает «тёмно-синий».

## План переписывания (ветка fix)

### Структура

```
transfermarkt_scrapper/
├── config.py            # API base, лимиты, Tier-1 список (лиги + сборные), env-переменные
├── client.py            # HTTP к transfermarkt-api: curl_cffi/requests, ретраи, rate limiter
├── cache.py             # SQLite resume-кэш
├── fetch/
│   ├── competitions.py  # competitions/search → лиги Tier-1
│   ├── clubs.py         # competitions/{id}/clubs → клубы лиги; clubs/{id}/profile
│   ├── rosters.py       # ★ clubs/{id}/players (1 запрос на команду) + national-teams/{id}/players
│   ├── profiles.py      # players/{id}/profile (точечно, для коллекционки)
│   ├── market_values.py # players/{id}/market_value (точечно)
│   └── coaches.py       # coaches/{id}/profile + парсинг /mitarbeiter/ для coach_id
├── build_canon.py       # сборка канон-JSON (чистая, не мутирует кэш)
├── download_images.py   # логотипы, фото, флаги (эквивалент tm_6/tm_7)
└── canon_schema.json    # JSON Schema канона (валидация выхода)
```

### Ключевые решения

1. **Rate limiter ≤2 rps к TM**: глобальный токен-бассейн, thread-safe, один на все воркеры.
   При 429 — circuit breaker: пауза, экспоненциальный backoff, уважать `Retry-After`.
   Не молотить ретраями при бане.
2. **Resume-кэш (SQLite)**: `requests(url PRIMARY KEY, status, payload, fetched_at)` — перед запросом
   проверяем, повторный прогон не ходит на TM. Краул можно прерывать и продолжать.
3. **Fetch-порядок**: competitions → clubs → rosters (основной источник составов) → точечно
   profiles/market_value для игроков коллекционки → coaches (+ /mitarbeiter/ для coach_id).
4. **Идемпотентность**: запись только в `prepared_*`/канон; входные файлы не перезаписываются.
   `build_canon` читает кэш и пишет заново.
5. **Выход — канон-JSON** по схеме из вики GameplayFootball ([[данные-из-transfermarkt]]): meta,
   competitions, clubs, national_teams, players, players_market_value, coaches.
6. **TLS-fingerprint**: `curl_cffi` (имитация Chrome) + ротация UA — против Cloudflare.
