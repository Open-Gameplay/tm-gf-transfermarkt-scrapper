## Цель

Реализовать переписанный скрейпер по дизайну из `docs/wiki/конвейер.md`: config + client (rate limiter, curl_cffi, ретраи, circuit breaker) + SQLite resume-кэш + fetch-модули + сборка канон-JSON. **Никакого кода не должно уходить в TM, пока экспериментально не установлена безопасная частота запросов.**

## Шаг 0 — экспериментально установить безопасный лимит запросов (обязательно, до любого массового сбора)

Значение «2 rps» из прошлых решений — **гипотеза, а не факт**. Нужно установить его экспериментально. Главный критерий — **не получить бан** (пользователя уже банили на TM надолго).

План:
1. Начни с консервативной частоты (0.5 rps, т.е. запрос каждые 2 c), сериями по 20–50 запросов.
2. Следи за: HTTP-статусами (особенно 429, 5xx), появлением капчи/блокировочной страницы (перехват по сигнатурам контента), задержками.
3. Плавно повышай (0.5 → 1 → 1.5 → 2 rps), между сериями пауза. Зафиксируй, где появляются первые признаки троттлинга.
4. Проверь **Retry-After**: если TM шлёт его в 429 — уважать и учесть в логике ретраев.
5. Результат: число «безопасных rps» для HTML-эндпоинтов, задокументированное в вики скрейпера (страница `конвейер.md` или новая — по правилам вики). Не полагайся на дефолт 2 rps вслепую.

## Шаг 1 — проверить, относится ли лимит к CDN картинок

Гипотеза: скачивание изображений с `img.a.transfermarkt.technology` (и других CDN-хостов) **может не ограничиваться** так же, как HTML-скрейпинг `www.transfermarkt.com`. Проверь экспериментально тем же способом (начни медленно, наращивай, следи за статусами). Зафиксируй вывод в вики: лимит CDN отдельно, если он другой. Это критично для `download_images.py` — если CDN не ограничен, картинки можно качать существенно быстрее.

## Шаг 2 — реализация по дизайну

Работай на отдельной ветке (например `scraper-v2` от `main`, либо на базе `fix` — реши и зафиксируй в вики). По дизайну из `конвейер.md`:

- `config.py` — API base, установленные экспериментально лимиты, Tier-1 список лиг/сборных.
- `client.py` — HTTP к API: curl_cffi (TLS-fingerprint Chrome) или requests, глобальный thread-safe rate limiter, ретраи с учётом Retry-After, circuit breaker при 429/бане.
- `cache.py` — SQLite resume-кэш (`requests(url PRIMARY KEY, status, payload, fetched_at)`): перед запросом проверять, повторный прогон не ходит на TM.
- `fetch/` — competitions → clubs → rosters (основной источник: `clubs/{id}/players`, 1 запрос на команду) → точечно profiles/market_value → coaches (+ `/mitarbeiter/` для `coach_id`).
- `build_canon.py` — сборка канон-JSON по схеме GF-вики, чистая и идемпотентная (не мутирует кэш и вход).
- `download_images.py` — логотипы/фото/флаги с учётом вывода Шага 1.
- Выход валидировать по `canon_schema.json` (JSON Schema).

Не начинай полный краул Tier-1 без подтверждённых лимитов и resume-кэша. Для проверки конвейера хватит 2–3 команд + 1 сборной.

## Критерии готовности

1. Эксперимент по лимитам проведён, результаты и безопасные rps (HTML и CDN раздельно) — в вики.
2. Скрейпер собирает Tier-1 (или пилотный набор) с resume-кэшем, без бана, идемпотентно.
3. Канон-JSON соответствует схеме; пробный конвертер в GF SQLite (минимальный, для проверки) не обязателен в этой сессии — только если успеешь.
4. `docs/wiki/` скрейпера обновлена, `log.md` дополнен записью `session`.

## Правила

- Код и комментарии — на английском, вики — на русском.
- **Лимиты к TM: не превышать установленные экспериментально; при 429/бане — остановиться, не молотить ретраями.**
- Все пути к TM — через локальный API (кроме `/mitarbeiter/` и CDN-картинок, где это обосновано).
- После содержательной правки — обнови вики (правила в AGENTS.md); хуки подскажут страницу по пути файла.
- Коммиты на английском, на ветке `scraper-v2` (или той, что выбрал), пушить можно, если пользователь разрешил.
- Обновляй `docs/wiki/открытые-вопросы.md` и `log.md` по ходу.
